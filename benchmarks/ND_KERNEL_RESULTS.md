# Nondominated kernel timings

Before/after for `archive.nondominated_mask` backends. `loop` is the default path and the BEFORE column. Generated by `python benchmarks/run_nd_kernel.py` on 2026-11-10, about 12:45 AM–12:53 AM ET. Warm-up excluded. Means are over seeds 7, 11, and 19. Peak alloc is `tracemalloc` after warm-up, not RSS.

## Hardware

- Linux 6.12.113+, Python 3.13.5, NumPy 2.5.4, Numba 0.68.1
- CPU: x86_64, 8 cores (Intel Xeon)
- Memory: 15 GiB host RAM
- GPU: none (`nvidia-smi` not present; Numba CUDA driver not found)
- CUDA backend: skipped

`kind=random` is a uniform [0, 1] cloud (most points are dominated; the compiled kernel exits early). `kind=front` is an analytic 2-D front, so every point is non-dominated and the inner loop runs to *n*. That is the worst case.

`tiled` does not meaningfully beat `loop` once *n* reaches a deep-profile archive (1,584). It also allocates an *n*×tile×*M* temporary (12.5 MB at n=10,000 vs 0.11 MB for `loop`). A broadcasted NumPy rewrite is not the win.

`jit` is the honest CPU after-column: 12× on a full front, hundreds to thousands of times on random clouds, and much less memory than `tiled`. `jit_parallel` helps the full-front worst case (55× at n=10,000) and can add thread-pool variance on easy random clouds (see n=10,000 random: mean 19 ms vs 1.1 ms serial).

Every timed cell matched the `loop` mask exactly.

## Realistic archive (ExactEw sweep, not isolated random)

Same box, `ExactEwMetropolisBackend` on a 12-bit linear pair of objectives. Default anneal, seeds 7 / 11 / 19: sampling ~34 ms, archive 1,440 rows. `nondominated_mask` on that archive:

| backend | mean ms | vs loop | match |
|---------|--------:|--------:|:-----:|
| `loop` | 74.7 | 1.00x | yes |
| `jit` | 2.43 | 31x | yes |

Deep-like schedule (11 weights, 24 warmup, 24 samples): sampling 39 ms, archive 1,584, `loop` 90 ms, `jit` 3.4 ms (27×). This cloud has duplicate non-dominated rows, so it is harder than a fresh random draw (those duplicates do not dominate each other, which delays early exit) and easier than a pure front.

## CUDA

Not measured. No device on this box. The kernel source is `unsga3_extropic.kernels.nondominated.ND_MASK_CUDA_SOURCE` (CuPy `RawKernel`) and the matching `numba.cuda.jit` kernel. Tests marked `gpu` skip when `cuda_available()` is false.

To fill this section on a machine with a GPU:

```bash
pip install -e ".[dev,kernels]"
python benchmarks/run_nd_kernel.py --out benchmarks/ND_KERNEL_RESULTS.md
```

If CuPy is installed and Numba CUDA is not, `backend='cuda'` uses the raw kernel string. Memory for the CUDA path is the input (*n*×*M* float64) plus an *n*-byte mask: about 160 KB at n=10,000, M=2, versus tens of megabytes for a materialized pairwise broadcast.
